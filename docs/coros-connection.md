# 高驰连接可靠性

高驰访问令牌被 userinfo 或 MCP 拒绝（HTTP 401）时，使用已保存的 refresh token 续期并重试一次；再次拒绝会报告连接失败并保留凭据。每次操作最多续期一次；只有 refresh token 的 `invalid_grant` 会清除连接并要求重新授权。

网络连接和读取分别设置 15 秒超时，每次请求另有 30 秒总期限，即使服务器持续发送数据也会结束等待。训练读取取消时会尝试断开当前连接，释放等待中的协程；底层 I/O 的实际结束仍受平台实现和超时影响。领取 ticket、交换 code、轮换 refresh token 及其保存作为不可取消的有限网络阶段执行，以减少一次性凭据已经使用但未保存结果的风险。阶段之间检查取消，不会继续启动下一阶段。网络中断或进程退出仍可能使服务器已消费的凭据无法恢复，用户需要重新授权。

加密存储沿用 v1 envelope。读取连接信息失败时，「我」页面显示错误，点击后可确认重置高驰连接；重置只删除该来源的连接文件，不删除 Room 中的训练记录，不会自动覆盖损坏文件。

领取会话、使用授权 ticket 和交换 code 在发送前记录已开始使用；如果响应丢失，后续不会自动重放这些一次性凭据，可在连接对话框取消连接并重新授权。尚未开始使用的阶段可继续。

实现上，HTTP 传输、共享请求校验、OAuth、MCP 协议和授权状态编解码分别维护；连接器组合 OAuth 与 MCP；授权状态以不可变值表达，持久化使用加密封套，阶段标志表示对应阶段是否已经开始。
